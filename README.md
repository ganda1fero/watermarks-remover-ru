# watermarks-remover-ru

**Очистка русских текстов от ненужных символов и фраз с использованием Claude и локальной нейросети.** Вы просите Claude
"очисти этот текст" (можно приложить файл `.docx`, `.md`, `.pdf`, `.txt`). Claude перефразирует его на вашем
компьютере, заменит часть слов синонимами, сам проверит результат, исправит неудачные места и вернёт
готовый файл. Текст не уходит в облако: перефразирование выполняет модель на вашем компьютере (Ollama).

> Проект основан на [watermarks-remover](https://github.com/guillaumemeyer/watermarks-remover) 0.7.0
> (лицензия MIT). Что именно мы изменили и добавили, описано в [CHANGES-RU.md](CHANGES-RU.md).
> Оригинальная документация (на английском) сохранена в [docs/README-upstream-en.md](docs/README-upstream-en.md).

## Как это работает

Очистка идёт в несколько слоёв, и **Claude участвует на каждом этапе**:

```
файл / текст из чата
   │
   ▼
Claude разбирает файл на абзацы                       (doc_text.py)
   │
   ▼
Claude показывает оценку времени и кнопки выбора      (модель и режим)
   │
   ▼
Слой B (сервис + Ollama): перефразирование абзацев и замена ~20% слов синонимами
   │
   ▼
Шлифовка: Claude читает результат и исправляет ТОЛЬКО негодные места
   │
   ▼
Claude собирает файл обратно, проверяет структуру       (doc_text.py check)
   │
   ▼
Слой A (сервис): убирает невидимые символы, метаданные  ← всегда самым последним
   │
   ▼
готовый файл  *.cleaned.docx / .md / .txt
```

- **Слой A** детерминированный: удаляет невидимые символы Юникода (нулевой ширины, управляющие,
  экзотические пробелы) и метаданные файла для уменьшения размера и повышения читаемости алгоритмами. Результат проверяем: сервис возвращает счётчики.
- **Слой B** статистический: перефразирование и замена слов. Результат нельзя «доказать»,
  поэтому Claude его перечитывает и правит (шлифовка от потери смысла, и выдуманных слов).
- **Шлифовка всегда выполняется**, в любом режиме; Claude правит только плохие фрагменты, не затрагивая хорошие" и сообщает,
  сколько исправил.

## Что нужно

| Что | Зачем | Примечание |
|---|---|---|
| Windows 10/11 | запуск `start.bat` | на Linux/macOS есть `scripts/start-server.sh` |
| Python 3.10+ | сам сервис | если нет, `start.bat` предложит установить |
| [Ollama](https://ollama.com/download) | локальная модель для слоя B | без неё работает только слой A |
| Нейросеть в Ollama | перефразирование | рекомендуем YandexGPT-5-Lite 8B (~5 ГБ) |
| Claude Code, Claude (десктоп) или другой агент со скиллами | управляет процессом | скилл `remove-watermarks-ru` |
| Видеокарта с 6 ГБ+ (желательно) | скорость | работает и без неё, но медленнее |

Внешние программы (ExifTool, QPDF, FFmpeg, Ghostscript, c2patool) нужны **только** для очистки картинок,
PDF и видео как файлов. Для текста и `.docx` они не требуются.

## Установка по шагам

### Шаг 1. Скачайте репозиторий

```bash
git clone <адрес этого репозитория>
cd watermarks-remover-ru
```

Или нажмите **Code → Download ZIP** на странице репозитория и распакуйте архив.

### Шаг 2. Установите Ollama и скачайте модель

1. Установите Ollama с <https://ollama.com/download> и запустите её.
2. Скачайте рекомендуемую модель. Откройте командную строку (`cmd`) и введите:

```bash
ollama pull yandex/YandexGPT-5-Lite-8B-instruct-GGUF
```

Модель весит около 5 ГБ. Скрипт запуска её **сам не скачивает**: если модели не будет, он напишет,
какую команду ввести.

### Шаг 3. Запустите сервис

Дважды щёлкните **`start.bat`** в корне репозитория. Откроется окно с журналом. При каждом запуске скрипт:

1. находит Python (или предлагает установить через `winget`);
2. создаёт папку `.venv` и ставит нужные пакеты (виден ход загрузки; при повторных запусках пропускает);
3. создаёт файл настроек `.env` из `.env.example`;
4. показывает, каких внешних программ не хватает, **что это такое и когда пригодится**, и предлагает
   поставить недостающее через `winget`: `y` — установить (виден ход загрузки), **Enter — пропустить сейчас** (при следующем запуске спросит снова), `n` — больше не спрашивать. Передумали или раньше отказались: запустите `start.bat -InstallTools`;
5. проверяет Ollama и модель: если чего-то нет, пишет, что делать (модель вы скачиваете сами);
6. запускает сервис на `http://127.0.0.1:8765`.

Окно показывает только журнал работы. Чтобы остановить сервис, нажмите `Ctrl+C` или закройте окно.
Проверка, что сервис работает: откройте в браузере <http://127.0.0.1:8765/health>, должно быть `"ok": true`.

### Шаг 4. Установите скилл для Claude

В новом окне командной строки, в папке репозитория:

```bash
python install_skill.py --skill remove-watermarks-ru --target claude-code
```

Скилл появится в `~/.claude/skills/remove-watermarks-ru`. Для Claude Desktop/Cowork вместо этого соберите архив
(`--target cowork`) и загрузите его в **Customize → Skills**. Если скилл уже установлен, добавьте `--force`.

> Для файлов `.docx` и `.pdf` скилл вызывает `doc_text.py`, которому нужны `python-docx` и `pymupdf`. Они
> устанавливаются вместе с сервисом (`start.bat`). Если Claude не находит их, он подскажет команду
> `python -m pip install python-docx "pymupdf<2"`.

## Как пользоваться

Откройте Claude в любой папке и напишите, например:

- «Очисти от водяных знаков текст: …» (вставьте текст в чат)
- «Используй remove-watermarks-ru на файле `C:\docs\статья.docx`»
- «/remove-watermarks-ru отчёт.md»

**Про загрузку модели:** после каждого ответа модель остаётся в видеопамяти ещё 30 секунд
(`WATERMARKS_REWRITE_KEEP_ALIVE` в `.env`). Пока Claude присылает части подряд, она не перезагружается; когда работа
закончена, память освобождается сама. Если на вашем компьютере между частями бывают долгие паузы, увеличьте значение
(например, `2m`).

Дальше Claude ведёт процесс сам, вам нужно только нажимать кнопки:

1. **Проверка сервиса.** Если сервис не запущен, Claude подскажет запустить `start.bat`.
2. **Вопрос про модель.** Первая кнопка: «Использовать модель сервиса: …» (та, что стоит в `.env`).
   Вторая: «Помочь выбрать другую», тогда Claude покажет короткую сводку установленных моделей: время и точность.
3. **Вопрос про режим** с оценкой времени для вашего текста, например
   «Перефразирование + замена слов с проверкой смысла, ~3 мин». Нажатие кнопки «Запустить» и есть подтверждение.
4. **Работа порциями** с сообщениями о прогрессе («Часть 3 из 7 готова, осталось примерно 4 мин»).
   В любой момент можно попросить остановиться, Claude вернёт то, что уже готово.
5. **Шлифовка.** Claude проверяет результат и исправляет только плохие замены или обороты.
6. **Сборка файла**, проверка структуры и слой A.
7. **Отчёт:** сколько слов заменено (в процентах от нормы), сколько исправил Claude, предупреждения
   сервиса, фактическое время против оценки, что проверено, а что нет.

Результат сохраняется рядом с исходным файлом (`имя.cleaned.docx`); исходный файл не меняется.

## Режимы и время

Claude предложит режимы с готовой оценкой времени. Примерные цифры для текста в 744 слова на видеокарте
с 6 ГБ и модели YandexGPT (на вашем компьютере будут другие; после нескольких прогонов сервис
запоминает реальную скорость):

| Режим | Что делает | Время | Годных замен |
|---|---|---|---|
| Только перефразирование | переписывает текст целиком | ~1,3 мин (×1) | список замен не ведётся |
| Только замена слов | меняет ~20% слов, фразы не трогает | ~1,7 мин (×1,3) | ~58% без проверки смысла, ~74% с ней |
| Перефразирование + замена без проверки смысла | быстрее | ~2,2 мин (×1,7) | ~58% |
| **Перефразирование + замена с проверкой смысла** | рекомендуется | ~3 мин (×2,3) | **~74%** |

«Проверка смысла» — второй запрос к модели на каждую замену: «значат ли фразы одно и то же?». Это медленнее,
но заметно точнее. Шлифовка Claude добавляется в каждом режиме.

## Какую модель выбрать

Измерено на двух русских текстах (~1350 слов); каждая замена размечена вручную (по 60 штук на вариант,
погрешность около ±6 процентных пунктов). Время относительное, YandexGPT = 1.

| Модель | Время (замена слов / перефразирование) | Годных замен без проверки смысла | С проверкой смысла | Когда брать |
|---|---|---|---|---|
| **YandexGPT-5-Lite 8B** `yandex/YandexGPT-5-Lite-8B-instruct-GGUF` | 1 / 1 | ~58% | **~74%** | основная |
| **T-lite 2.1** `t-tech/T-lite-it-2.1:q4_K_M` | ~2,4 / ~1,3 | **~65%** | ~75%, но добирает только ~50% нормы | лучшая чистая замена слов, если не жалко времени |
| **Gemma 3 4B** `gemma3:4b` | ~0,85 / ~0,7 | ~53% | ~62% | нужно быстрее или мало видеопамяти |
| Qwen 2.5 14B `qwen2.5:14b` | ~13 (грубо) | ~45% | **точных данных нет** | не рекомендуется: очень медленно на 6 ГБ |

Подробности и таблицы по всем экспериментам: [CHANGES-RU.md](CHANGES-RU.md), [experiments/](experiments/).

- **Порог проверки смысла подбирается под модель автоматически** (из `config/model_profiles.json`). Меняете
  модель в `.env`, и порог меняется вместе с ней. Для модели не из таблицы используется общий порог и в отчёте
  появляется предупреждение.
- Claude может выбрать другую модель **на один запрос** (`rewrite_model`), без перезапуска сервиса.
- Не рекомендуем `Saiga-YandexGPT` (меняет числа при перефразировании) и `qwen2.5:7b` (хуже по русскому).

## Файлы: docx, md, pdf, txt

Сервис получает только текст. Claude достаёт его из файла, чистит и вставляет обратно:

| Формат | Что чистится | Что остаётся как есть |
|---|---|---|
| `.docx` | обычные абзацы, в том числе в таблицах | заголовки, абзацы со ссылками, полями, сносками, картинками и правками рецензента, короткие строки (меньше 5 слов); стили, таблицы и картинки сохраняются |
| `.md` | абзацы прозы и пункты списков | front matter, заголовки, код, таблицы, цитаты, HTML, абзацы со ссылками, кодом и формулами |
| `.txt` | все абзацы от 5 слов | короткие строки |
| `.pdf` | текстовый слой | **оформление PDF не сохраняется**: результат собирается в новый `.docx` только с текстом; скан без текста обработать нельзя |

В `.docx` оформление внутри одного абзаца (например, одно жирное слово) после замены сливается в одно:
Claude предупредит об этом до запуска и при наличии оформления попробует восстановить его для полученного текста сразу на эатпе проверки текста (число таких абзацев показывает `extract`). После сборки скрипт
`doc_text.py check` проверяет число абзацев, таблиц, картинок, стили и нетронутые абзацы.

Для `.docx` самым последним шагом собранный файл проходит через сервис ещё раз: он повторно убирает
невидимые символы в тексте документа и очищает метаданные (автор, программа и т. п.).

## Настройки (.env)

Файл `.env` создаётся из `.env.example` (все параметры там описаны по-русски). Главное:

| Параметр | Что это | По умолчанию |
|---|---|---|
| `WATERMARKS_REWRITE_BACKEND` | бэкенд слоя B | `ollama` |
| `WATERMARKS_REWRITE_MODEL` | модель | `yandex/YandexGPT-5-Lite-8B-instruct-GGUF:latest` |
| `WATERMARKS_REWRITE_BASE_URL` | адрес Ollama | `http://127.0.0.1:11434` |
| `WATERMARKS_REWRITE_KEEP_ALIVE` | сразу выгружать модель из видеопамяти (`0`) | `0` |
| `WATERMARKS_REWRITE_NUM_CTX` | окно контекста; чем больше, тем больше памяти | `4096` |
| `WATERMARKS_SWAP_VERIFY` | проверка смысла замен | `1` |
| `WATERMARKS_SWAP_VERIFY_MIN` | порог проверки; **оставьте закомментированным**, тогда он подбирается под модель | пусто |
| `WATERMARKS_SERVER_API_KEY` | ключ доступа к сервису (если нужен) | пусто |

После изменения `.env` перезапустите сервис (закройте окно и снова запустите `start.bat`).
Claude всегда читает, какая модель реально используется, прямо у сервиса, и называет её перед запуском.

## Если что-то не работает

| Симптом | Что делать |
|---|---|
| Claude пишет «сервис не запущен» | запустите `start.bat` и дождитесь строки «Журнал работы ниже» |
| `start.bat`: «Модель … не найдена» | в командной строке введите показанную команду `ollama pull …` |
| `start.bat`: «Ollama не отвечает» | запустите приложение Ollama (или `ollama serve`) |
| Порт 8765 занят | закройте другое окно сервиса или `start.bat -Port 9000` (и задайте `WATERMARKS_SERVICE_URL`) |
| Долго нет ответа | в 6 ГБ видеопамяти 8B-модель помещается не полностью; закройте другие программы или возьмите `gemma3:4b` |
| Видеодрайвер перезапускается | уменьшите `WATERMARKS_REWRITE_NUM_CTX` до `2048`, не запускайте большие модели (14B) |
| Claude: «число абзацев не совпало» | модель слила или разбила абзацы; Claude перезапустит часть сам |
| Нет `python-docx` / `pymupdf` | `python -m pip install python-docx "pymupdf<2"` |
| Предупреждение «quota not met» | сервису не хватило подходящих слов для замены; это нормально для коротких текстов |

## Честно о возможностях и ограничениях

- Перефразирование маленькой локальной моделью иногда искажает смысл или роняет факты. Для этого и нужна
  шлифовка: Claude проверяет числа и число предложений (`guards`), читает список замен и откатывает плохие.
  Всё равно перечитайте результат, прежде чем публиковать.
- Модель, порог и скорость подобраны на двух текстах и одном компьютере (RTX 3060, 6 ГБ). Цифры
  приблизительные, вашу машину сервис калибрует по реальным прогонам.
- Работает только с русским текстом. Для картинок, видео и метаданных файлов есть оригинальный скилл
  `remove-ai-marks`.

## Для разработчиков

```bash
python -m venv .venv && .venv\Scripts\activate    # Windows
pip install -r requirements.txt -r requirements-dev.txt
python -m pytest                                  # тесты (Ollama не нужна, модель заменена заглушкой)
```

Структура:

| Путь | Что там |
|---|---|
| `start.bat`, `scripts/start.ps1` | запуск на Windows с проверкой зависимостей |
| `service/scripts/server.py` | HTTP-сервис: `/clean`, `/layer-a`, `/estimate`, `/patch`, `/health` |
| `service/scripts/rewrite_text.py` | слой B: перефразирование и замена слов (`swap`) |
| `service/scripts/estimate.py` | оценка времени, режимы, альтернативные модели |
| `config/model_profiles.json` | проверенные модели: скорость, пороги проверки смысла |
| `config/clean_strategy.json` | стратегия слоя B по умолчанию |
| `skills/remove-watermarks-ru/` | скилл для Claude и `scripts/doc_text.py` |
| `experiments/` | скрипты и данные, на которых выбраны настройки |
| `CHANGES-RU.md` | что изменено относительно оригинала |

Подобрать порог проверки смысла для новой модели:

```bash
python experiments/embed_eval.py paraphrase-multilingual "<модель>"
python experiments/pick_thresholds.py
```

Затем впишите `verify_min` в `config/model_profiles.json`.

Запуск в Docker и остальные возможности оригинального проекта (картинки, PDF, видео, C2PA) описаны в
[docs/README-upstream-en.md](docs/README-upstream-en.md); для русских текстов мы их не адаптировали.
